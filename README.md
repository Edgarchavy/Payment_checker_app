# Интеллектуальная система сверки данных банковских документов

Курсовой проект по теме:

**«Разработка интеллектуальной системы сверки данных: сопоставление сущностей из накладных и банковских выписок с использованием нечетких алгоритмов»**

Проект представляет собой локальный Python-прототип для автоматизированной проверки факта оплаты. Система принимает банковские документы в виде PDF-чеков, фотографий или скриншотов, извлекает из них реквизиты платежа и сопоставляет их с ожидаемыми данными.

## Назначение проекта

В реальных учебных, бухгалтерских или административных процессах часто возникает ситуация, когда клиент отправляет подтверждение оплаты, а ответственному лицу нужно проверить:

- действительно ли оплачена нужная сумма;
- тому ли получателю отправлены деньги;
- совпадает ли плательщик;
- соответствует ли назначение платежа или код операции;
- можно ли считать документ подтверждением оплаты.

Ручная проверка большого количества чеков занимает время и может приводить к ошибкам. Данный проект демонстрирует, как такую задачу можно автоматизировать с помощью интеллектуальной системы обработки документов.

## Что умеет система

Система поддерживает два режима работы:

- **Одиночная проверка**: пользователь вручную вводит ожидаемые реквизиты платежа и загружает один банковский документ.
- **Пакетная проверка**: пользователь загружает таблицу ожидаемых платежей в формате CSV/XLSX и набор банковских документов, после чего система автоматически сопоставляет документы со строками таблицы.

Основные возможности:

- извлечение текста из PDF без OCR, если в документе есть текстовый слой;
- предварительная обработка фотографий и скриншотов перед OCR;
- локальное OCR-распознавание через Tesseract;
- выделение платежных сущностей: сумма, валюта, получатель, плательщик, дата, RRN, MCC, код авторизации, назначение платежа;
- нечеткое сопоставление реквизитов;
- расчет процентной оценки соответствия `score`;
- формирование объяснимого результата проверки.

## Логика принятия решения

В проекте используются критические и дополнительные признаки.

Критические признаки:

- сумма платежа;
- получатель платежа.

Если сумма или получатель не соответствуют ожиданию, система не считает документ подтверждением оплаты, даже если остальные признаки похожи.

Дополнительные признаки:

- плательщик;
- назначение платежа;
- дата;
- валюта;
- RRN, MCC или иной код операции.

По совокупности признаков рассчитывается `score` - процент соответствия ожидаемого платежа и банковского документа.

Возможные статусы:

- **Оплачено** - документ надежно соответствует ожидаемому платежу;
- **Возможное совпадение** - критические признаки похожи, но есть расхождения по дополнительным атрибутам;
- **Не оплачено** - документ не найден или критические признаки не совпадают.

## Как работает обработка документа

Общий конвейер обработки:

1. Пользователь задает ожидаемые реквизиты или загружает таблицу ожидаемых платежей.
2. Пользователь загружает PDF, фото или скриншоты банковских документов.
3. Для PDF выполняется извлечение текстового слоя.
4. Для изображений выполняется предобработка и OCR через Tesseract.
5. Из текста выделяются платежные реквизиты.
6. Реквизиты нормализуются и сопоставляются с ожидаемыми данными.
7. Система формирует статус, `score` и причины расхождений.

## Структура проекта

```text
payment_checker_app/
├── run_localhost_app.bat
├── README.md
└── python_coursework/
    ├── local_webapp.py
    ├── main.py
    ├── build_demo_expected_payments.py
    ├── requirements.txt
    └── check_pipeline/
        ├── pdf_text.py
        ├── image_preprocess.py
        ├── ocr_tesseract.py
        ├── field_extractor.py
        ├── manual_match.py
        ├── entity_matching.py
        ├── matcher.py
        ├── models.py
        ├── io_utils.py
        ├── reference_builder.py
        └── xlsx_writer.py
```

Ключевые модули:

- `local_webapp.py` - локальный веб-интерфейс приложения;
- `pdf_text.py` - извлечение текста из PDF-файлов;
- `image_preprocess.py` - улучшение изображений перед OCR;
- `ocr_tesseract.py` - запуск Tesseract OCR;
- `field_extractor.py` - выделение реквизитов из текста;
- `manual_match.py` - одиночная проверка одного документа;
- `entity_matching.py` - пакетное нечеткое сопоставление ожидаемых платежей и банковских документов.

## Запуск приложения

На Windows можно запустить:

```powershell
run_localhost_app.bat
```

Или вручную:

```powershell
python python_coursework\local_webapp.py
```

После запуска открыть в браузере:

```text
http://127.0.0.1:8000
```

## Зависимости

Для базовой работы с PDF используется код проекта и стандартная библиотека Python.

Для OCR изображений нужен Tesseract OCR. Его можно установить отдельно и указать путь к `tesseract.exe` через переменную окружения:

```powershell
set TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

Для обработки изображений используется Pillow:

```powershell
pip install -r python_coursework\requirements.txt
```

## Особенности реализации

Проект не использует внешние API для обработки банковских документов. Распознавание и сверка выполняются локально. Это важно для демонстрационного прототипа, поскольку банковские документы могут содержать чувствительные данные.

В репозитории не размещаются реальные PDF-чеки, фотографии, скриншоты, таблицы с персональными данными и результаты обработки. Репозиторий содержит только исходный код приложения.

## Практическое применение

Прототип может быть использован как основа для:

- проверки оплат по выставленным счетам;
- сверки чеков с таблицей ожидаемых платежей;
- автоматизации первичного учета оплат;
- учебной демонстрации интеллектуальной обработки банковских документов;
- дальнейшего развития в сторону обработки банковских выписок и накладных.
