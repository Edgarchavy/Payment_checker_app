# Интеллектуальная система сверки данных банковских документов

**Тема курсового проекта:**  
«Разработка интеллектуальной системы сверки данных: сопоставление сущностей из накладных и банковских выписок с использованием нечетких алгоритмов»

**Автор:** Грушевский Эдгар Игоревич  
**Группа:** ИИ-231  
**Язык реализации:** Python  
**Тип приложения:** локальное веб-приложение

## Краткое описание

Проект представляет собой прототип интеллектуальной системы для автоматизированной проверки факта оплаты. Пользователь загружает банковский документ в виде PDF-чека, фотографии или скриншота, а система извлекает из него платежные реквизиты и сопоставляет их с ожидаемыми данными.

Система может использоваться в учебных, бухгалтерских и административных процессах, где необходимо быстро проверить, действительно ли клиент оплатил нужную сумму нужному получателю по заданному назначению платежа.

## Основные возможности

- Одиночная проверка одного банковского документа по вручную введенным ожидаемым реквизитам.
- Пакетная проверка: сопоставление таблицы ожидаемых платежей `CSV/XLSX` с набором банковских документов.
- Извлечение текста из PDF-файлов без OCR, если в документе есть текстовый слой.
- Предварительная обработка фотографий и скриншотов перед OCR.
- Локальное OCR-распознавание изображений через Tesseract.
- Выделение платежных сущностей: сумма, валюта, получатель, плательщик, дата, RRN, MCC, код авторизации, назначение платежа.
- Нечеткое сопоставление реквизитов и расчет процентной оценки соответствия `score`.
- Формирование объяснимого результата проверки с причинами расхождений.

## Логика работы системы

Общий конвейер обработки документа:

1. Пользователь задает ожидаемые реквизиты или загружает таблицу ожидаемых платежей.
2. Пользователь загружает PDF, фото или скриншоты банковских документов.
3. Для PDF выполняется извлечение текстового слоя.
4. Для изображений выполняется предобработка и OCR через Tesseract.
5. Из полученного текста выделяются платежные реквизиты.
6. Реквизиты нормализуются и сопоставляются с ожидаемыми данными.
7. Система формирует статус, `score` и причины расхождений.

При принятии решения сумма и получатель считаются критическими признаками. Если сумма или получатель не соответствуют ожиданию, документ не признается подтверждением оплаты даже при совпадении других атрибутов.

Возможные статусы:

- **Оплачено** - документ надежно соответствует ожидаемому платежу.
- **Возможное совпадение** - найден похожий документ, но есть расхождения по дополнительным признакам.
- **Не оплачено** - подходящий документ не найден или критические признаки не совпадают.

## Требования

- Python 3.12 или совместимая версия Python 3.x.
- `pip` для установки зависимостей.
- Tesseract OCR для распознавания фотографий и скриншотов.

Python-зависимости указаны в файле:

```text
requirements.txt
```

На текущем этапе проект использует:

```text
Pillow>=10.0.0
```

## Установка зависимостей

В корне проекта выполнить:

```powershell
pip install -r requirements.txt
```

Для OCR изображений нужно установить Tesseract OCR отдельно и при необходимости указать путь к `tesseract.exe`:

```powershell
set TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
```

Если OCR для фотографий не требуется, PDF-файлы с текстовым слоем могут обрабатываться без Tesseract.

## Как запустить

Вариант 1. Запуск через BAT-файл на Windows:

```powershell
run_localhost_app.bat
```

Вариант 2. Ручной запуск:

```powershell
python python_coursework\local_webapp.py
```

После запуска открыть в браузере:

```text
http://127.0.0.1:8000
```

## Как проверить работу

Для одиночной проверки:

1. Открыть локальный интерфейс.
2. Ввести ожидаемую сумму, валюту, получателя и дополнительные реквизиты.
3. Загрузить PDF-чек, фотографию или скриншот.
4. Получить статус проверки и причины расхождений.

Для пакетной проверки:

1. Подготовить таблицу ожидаемых платежей в формате `CSV` или `XLSX`.
2. Загрузить таблицу в интерфейс.
3. Загрузить набор банковских документов.
4. Получить таблицу результатов со статусами, найденными файлами и `score`.
